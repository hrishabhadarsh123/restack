Architecture

Three passes, one context budget, and verification between every batch.

Module map

Pass 1 — the planning call

The scanner reads every candidate file into memory once. The packer then fills a ~180k-token budget by role priority — entry → config → route → shared → templates/styles/tests — always smaller files first so more distinct files survive. Entry/config files may borrow from the summary budget because the planner needs them verbatim.

Oversized files are summarized head+tail with an explicit truncation marker; files that no longer fit remain visible in the inventory so the plan can still reference them. The response must be a bare JSON object matching the MigrationPlan schema — the parser tolerates markdown fences and surrounding prose, and a wrong target field is overridden with a warning.

The plan is the contract for everything downstream: conversion waves, batch prompts, and the review pass all read from plan.json, never from a second opinion.

Pass 2 — conversion & repair

Sources are grouped into the plan's dependency waves, then split into batches of at most 3 files / 24k tokens. Independent batches run with bounded concurrency (--workers). Each call gets the same system prompt — target conventions plus the plan's decision, route and mapping tables — marked cacheable so repeat batches pay cache-read prices on the stable prefix. 

<file path="app/users/page.tsx">
...complete file content...
</file>

The parser extracts <file path="..."> blocks, rejecting absolute paths and .. traversal. After writing outputs, the profile's verifier runs:

TargetVerification
nextjs tsc --noEmit (local bin or PATH); bracket-balance fallback when no compiler is available
fastapi ast.parse every file; import smoke test of main.py when fastapi/pydantic are installed

Failures feed the first ≤20 compiler errors back to Claude for one bounded repair round; batches that still fail are recorded with status failed and their errors, and conversion continues.

State, resume & cost

After every batch, .restack/state.json records each source's status, outputs and attempts. --resume reloads the saved plan and skips sources already converted or repaired — a plan-hash mismatch warns that the source tree changed. Before every API call, the projected cost (input estimate + expected output) is checked against --max-cost; exceeding it raises CostLimitError and the run stops cleanly with spend so far reported.

Extending

New targets are a ModernTarget entry plus a profile: conventions text, static scaffold files, and a verify() implementation. New legacy stacks need detection markers in the scanner — see the django stack (issue #11) for a worked example: detection markers, STACK_CONVERSION_NOTES prompt guidance, role classification and a fixture with e2e coverage. The test suite runs entirely against a mocked client — see CONTRIBUTING.md for the checklist.
