Walkthrough: PHP/jQuery → Next.js

The bundled fixture at test/fixtures/php-app is a tiny legacy shop: an entry router, two pages, a JSON endpoint, shared includes, and a jQuery search box. Here's the full conversion, step by step.

The legacy project

php-app/
├── index.php              # entry: ?page= router
├── includes/
│   ├── db.php             # PDO helpers (shared)
│   └── helpers.php        # e(), format_money() (shared)
├── pages/
│   ├── home.php           # static welcome
│   ├── users.php          # users table + search input
│   └── orders.php         # open orders list
├── api/users_search.php   # JSON search endpoint
├── js/users.js            # jQuery: live search
├── style.css              # global styles
└── .env                   # DB credentials (sensitive!)

$ restack scan test/fixtures/php-app

Estimated planning-call input: ~4.8k tokens ≈ $0.25 (sonnet, one-shot plan)
.env is detected and excluded before any API call — its contents never reach the model. Target is implied: php-jquery → nextjs.

Step 2 — restack convert --dry-run (the plan)

One Claude call over the packed project produces .restack/plan.json. Representative (abridged) plan for this fixture: 

{
  "target": "nextjs",
  "summary": "PHP multi-page shop to Next.js App Router: server-rendered
              pages, JSON search endpoint, jQuery search as a client component.",
  "decisions": [
    { "topic": "data access",  "choice": "PDO helpers centralize into lib/db.ts with parameterized queries" },
    { "topic": "search box",   "choice": "jQuery live search becomes a 'use client' component with fetch + useTransition" },
    { "topic": "escaping",     "choice": "drop e()/htmlspecialchars — React escapes by default" },
    { "topic": "config",       "choice": "DB_* env vars via process.env, documented in .env.example" }
  ],
  "dependencies": ["next", "react", "react-dom"],
  "fileMappings": [
    { "source": "includes/db.php",       "targets": ["lib/db.ts"],                      "note": "PDO -> libsql/pool" },
    { "source": "includes/helpers.php",  "targets": ["lib/format.ts"],                  "note": "only format_money survives" },
    { "source": "index.php",             "targets": ["app/page.tsx"],                   "note": "home route" },
    { "source": "pages/users.php",       "targets": ["app/users/page.tsx"],             "note": "server-rendered table" },
    { "source": "pages/orders.php",      "targets": ["app/orders/page.tsx"],            "note": "open orders" },
    { "source": "api/users_search.php",  "targets": ["app/api/users/search/route.ts"],  "note": "GET handler" },
    { "source": "js/users.js",           "targets": ["components/UserSearch.tsx"],      "note": "client component" },
    { "source": "style.css",             "targets": ["app/globals.css"],                "note": "as-is" }
  ],
  "routeMappings": [
    { "from": "index.php?page=users",       "to": "/users",              "method": "GET" },
    { "from": "index.php?page=orders",      "to": "/orders",             "method": "GET" },
    { "from": "api/users_search.php?q=...", "to": "/api/users/search",   "method": "GET" }
  ],
  "droppedFiles": [
    { "path": "pages/home.php", "reason": "merged into app/page.tsx (index.php)" },
    { "path": ".env",           "reason": "replaced by .env.example guidance" }
  ],
  "conversionOrder": [
    ["includes/db.php", "includes/helpers.php"],
    ["pages/users.php", "pages/orders.php", "api/users_search.php"],
    ["js/users.js", "style.css"]
  ],
  "risks": [
    "users.php renders user input unescaped before jQuery re-renders it — XSS in the legacy app, fixed by React escaping",
    "search endpoint uses LIKE with a bound param already; keep it that way"
  ]
}

Waves are the dependency DAG: shared libs first, then routes, then the client component and styles. Every source appears exactly once.

Step 3 — restack convert

The plan is executed wave by wave, ≤3 sources per batch, with tsc --noEmit after each batch and one bounded repair round. Representative terminal transcript: 

$ restack convert test/fixtures/php-app --out converted

Run it: cd converted && npm install && npm run dev
The 🔧 line is the repair loop in action: the first generated route failed tsc, the compiler errors were fed back to Claude, and the re-emitted file passed. Failed batches would be listed with ✗ and recorded in .restack/state.json for --resume.

The result

converted/
├── app/
│   ├── api/users/search/route.ts   # from api/users_search.php
│   ├── users/page.tsx              # from pages/users.php
│   ├── orders/page.tsx             # from pages/orders.php
│   ├── page.tsx                    # from index.php
│   ├── layout.tsx                  # static scaffold
│   └── globals.css                 # from style.css
├── components/
│   └── UserSearch.tsx              # from js/users.js  ("use client")
├── lib/
│   ├── db.ts                       # from includes/db.php
│   └── format.ts                   # from includes/helpers.php
├── package.json · tsconfig.json · next.config.mjs   # static scaffold
└── .restack/
    ├── plan.json                   # the plan (resume reuses it)
    └── state.json                  # checkpoint: per-source status

The jQuery search loop is now a client component; the users table is a server component that queries through lib/db.ts; and the legacy XSS risk the plan flagged is gone because React escapes output by default.
